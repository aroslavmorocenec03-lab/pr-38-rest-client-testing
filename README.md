# Практична робота №38

## Тестування REST API-ендпойнтів через REST Client

**Мета:** перевірити повний CRUD-цикл для поштового відправлення, проаналізувати HTTP-статуси, заголовки й JSON та підтвердити фактичну зміну даних.

Основний результат роботи — **[requests.http](requests.http)**: один файл із десятьма запитами в логічному порядку. Для самостійного запуску включено сервер **PostService** із ПР-37. Розширення **`humao.rest-client` версії 0.25.1** встановлено у VS Code з Marketplace.

## Запуск сервера

Потрібен **.NET SDK 10**. Завантажте репозиторій через **Code → Download ZIP**, розпакуйте та відкрийте термінал у кореневій папці.

```powershell
dotnet build PostService/PostService.csproj
dotnet run --project PostService
```

Адреса цього проєкту — **`http://localhost:5050`**; вона відповідає `@baseUrl` у файлі запитів. Сервер працює, поки відкритий процес; зупинення — Ctrl+C. Після перезапуску знову створюються три початкові відправлення з Id 1, 2, 3.

## Виконання у VS Code

1. Відкрийте папку проєкту у VS Code.
2. У розділі Extensions знайдіть **REST Client**, ідентифікатор **humao.rest-client**, та встановіть його, якщо він відсутній. Рекомендацію додано в `.vscode/extensions.json`.
3. Відкрийте `requests.http` і переконайтеся, що режим мови — **HTTP**.
4. Надсилайте блоки **01 → 10** по черзі через **Send Request** над запитом або **Ctrl+Alt+R**, коли курсор розміщений у потрібному блоці.
5. У відповіді перевіряйте статус, заголовки та тіло. Для POST зверніть увагу на `Location`; для DELETE — на відсутність тіла.

### Автоматичне підставлення Id

POST має ім’я `createPosting`, задане коментарем `# @name createPosting`. Наступні GET, PUT і DELETE звертаються до:

```http
GET {{baseUrl}}/postings/{{createPosting.response.body.$.id}}
```

Тому не потрібно вручну вгадувати Id. Спочатку виконайте блок 04 з POST — REST Client має отримати його відповідь, перш ніж розв’язувати посилання. Після перезапуску сервера виконайте сценарій знову від початку.

Синтаксис іменованих запитів, змінних відповідей та надсилання описано в [офіційному README REST Client](https://github.com/Huachao/vscode-restclient#request-variables).

## Сценарій у requests.http

| № | Запит | Очікувана перевірка |
| --- | --- | --- |
| 01 | `GET /postings` | 200, початковий список у JSON |
| 02 | `GET /postings/1` | 200, наявний запис |
| 03 | `GET /postings/999999` | 404, відсутній запис |
| 04 | `POST /postings` | 201, створений запис, `Location` |
| 05 | `GET /postings` | 200, новий запис є у списку |
| 06 | `GET /postings/{createdId}` | 200, значення до редагування |
| 07 | `PUT /postings/{createdId}` | 200, оновлений запис |
| 08 | `GET /postings/{createdId}` | 200, підтверджені збережені зміни |
| 09 | `DELETE /postings/{createdId}` | 204, порожнє тіло |
| 10 | `GET /postings/{createdId}` | 404, видалення підтверджено |

Кожному запиту передує `###`; POST і PUT мають `Content-Type: application/json`, порожній рядок і JSON-тіло.

У запитах використано `"Department"` та `"Courier"`, як у завданні. Для сумісності цих рядкових значень у сервері додано `JsonStringEnumConverter`. Він також серіалізує спосіб доставки у відповіді як назву. Решта моделі та CRUD-логіки з ПР-37 збережена: список у пам’яті, серверні Id, UTC-час створення та статуси 200/201/204/404.

## Фактичні результати

Збірка завершилася без помилок і попереджень. Додатковий сценарій PowerShell 7 виконав **саме десять блоків `requests.http`**, підставив Id із відповіді POST та перевірив статуси й стан даних: **10/10 успішно**.

```powershell
./scripts/Verify-Requests.ps1
```

Це автоматична перевірка HTTP, окрема від натискання Send Request у VS Code. Повний фактичний протокол — [reports/http-results.txt](reports/http-results.txt). Порівняння та відповіді на контрольні запитання — [reports/REPORT.md](reports/REPORT.md).
